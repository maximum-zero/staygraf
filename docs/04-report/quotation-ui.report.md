> **Feature**: quotation-ui
> **Date**: 2026-08-21
> **Match Rate**: 97%

## 요약

장바구니에서 선택한 구매 가능 상품을 기준으로 수신 정보를 입력하고, 현재 가격과 배송 조건을 다시 검증한 뒤 일반 견적서 형식으로 미리보기·발행·조회하는 전체 사용자 여정을 구현했다. 데스크톱 인쇄와 모바일 PDF 저장 안내를 제공하며, 발행본은 이후 장바구니나 상품 정보 변경에 영향을 받지 않는 스냅샷으로 보관한다.

현재 인증·발행·저장은 모의 회원과 브라우저 저장소를 사용한다. UI와 저장 책임은 store·repository로 분리해 실제 회원 API, 견적서 API와 서버 PDF 생성으로 교체할 수 있다.

## 완료 기능

- 장바구니 선택 묶음의 견적 초안 생성
- 비회원 로그인과 안전한 견적 작성 화면 복귀
- 견적명·수신처·담당자·연락처·이메일 입력 및 자동 임시 저장
- 미리보기·발행 직전 현재 상품 가격·판매 상태·배송 조건 재검증
- 변경 사항 반영 후 재확인하는 2단계 발행 보호
- 본품·추가 상품·선불 배송비의 독립 견적 행 생성
- `[브랜드] 상품명`, 옵션, 수량, 단위, 단가, 공급가액, 세액, 금액 표기
- 타일 규격·장수/BOX·면적/BOX·총 주문 면적 표기
- 인쇄 규격·옵션 최대 2줄 압축과 수량 1의 중복 총면적 제거
- 추가 상품의 가짜 옵션 제거, 빈 옵션 셀, `1-1` 종속 번호와 `└` 장식선 적용
- 개별 화물 운송 착불 제외와 직접 수령 0원 처리
- 한글 견적 금액과 숫자 총액 병기
- 견적번호, 견적일, 14일 유효기간, 유효·만료 상태
- 발행 시점 공급자·수신자·품목·금액 스냅샷
- 중복 발행 방지와 회원별 견적 이력·상세 조회
- 데스크톱 인쇄와 모바일 PDF 저장 안내
- A4 세로 출력, 반복 표 머리글과 페이지 분할 제어
- 가로형 `받는 분`·`공급자` 정보 블록과 얇은 총액 밴드
- 실제 `210mm` 화면 미리보기와 899px 이하 읽기형 문서 재배치
- 인쇄 시 9pt 이상 글자와 화면 반응형 규칙의 분리
- 좌측 정렬된 5% 순번 열과 `수량 → 단위` 순서의 8열 가변 행
- 품목표 우측 상단 `(단위: 원)`과 합계 금액의 `원` 표기
- 표 내부 배송 그룹 행과 품목 번호 반복을 제거하고 표 아래 배송 방식·비용 조건으로 이동
- 오류 인접 안내, 포커스 이동·복귀, 44px 조작 영역, reduced motion

## UI UX Pro Max 적용 결과

- 입력 오류를 필드 가까이에 배치하고 첫 제출 오류로 포커스를 이동했다.
- 가격 변경과 발행 확인은 경고창의 초기 포커스, Escape, 트리거 복귀를 지원한다.
- 확인창은 180ms 전환만 사용하고 reduced-motion 환경에서는 모션을 제거했다.
- 모바일에서는 가로로 축소한 A4를 보여주지 않고 같은 의미의 품목 표를 세로 문서 행으로 재배치했다.
- 주요 버튼과 입력은 44px 이상의 조작 영역을 유지하고 visible focus를 적용했다.
- 문서 화면과 인쇄 결과가 같은 데이터·마크업 원본을 사용하도록 구성했다.
- 화면용 899px 카드 규칙이 인쇄에 섞이지 않도록 print에서 A4 2열 구조를 명시적으로 복원했다.

## 유지할 결정

- 견적서는 선택 장바구니를 복사한 초안에서 시작하되 발행 직전까지 현재 상품 조건을 다시 검증한다.
- 발행된 견적서는 이후 가격·주소·장바구니 변경과 분리된 스냅샷이다.
- 견적서 품명에는 브랜드를 포함하고 컬렉션은 별도 열로 두지 않는다.
- 옵션은 품명과 분리해 읽되 추가 상품은 본품 번호에 종속된 번호를 사용한다.
- 할인은 정가와 적용 단가가 다를 때만 견적 행과 합계에 나타난다.
- 모바일 PDF는 브라우저의 시스템 인쇄·공유 기능을 사용하고 현재 단계에서 별도 PDF 생성 라이브러리를 추가하지 않는다.

## Learning Points

- 작성 중 견적과 발행된 견적은 변경 가능 여부가 다른 데이터다.
- 발행 직전 재검증은 사용자가 오래된 가격으로 문서를 확정하는 일을 막는다.
- 인쇄 CSS는 화면 반응형과 별도로 페이지 크기와 분할 규칙을 다뤄야 한다.
- 브라우저 저장소도 repository 뒤에 두면 향후 API 전환 범위를 줄일 수 있다.
