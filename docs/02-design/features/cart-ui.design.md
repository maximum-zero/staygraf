## 1. 구현 대상

상품 상세에서 선택한 본품 옵션·규격·수량·추가 상품·배송 방법을 하나의 묶음으로 저장한다. `/cart`에서는 현재 상품 데이터와 저장 스냅샷을 비교한 뒤 배송 방식별로 묶어 보여주고, 선택된 묶음만 주문 또는 견적 흐름으로 전달한다.

실제 서버와 인증은 연결하지 않는다. 따라서 장바구니는 브라우저 저장소로 동작하며 주문·견적 버튼은 다음 화면의 경계를 설명하는 피드백까지 제공한다.

## 2. 페이지와 이동

| 화면 | 경로 | 역할 |
|---|---|---|
| 상품 상세 | `/products/[id]` | 현재 구매 구성을 장바구니에 저장 |
| 장바구니 | `/cart` | 배송 그룹별 검토·선택·수정 |
| 상품 목록 | `/shop/tile?type=tile` | 빈 장바구니의 복귀 목적지 |

- 헤더 장바구니 아이콘은 `/cart` 링크이며 묶음 수를 배지로 표시한다.
- 장바구니에 담은 뒤에는 토스트에서 `장바구니 보기`를 제공한다.
- `선택 상품 주문`과 `견적서 만들기`는 로그인과 후속 화면이 아직 없음을 명확히 알린다.

## 3. 상태 모델

```ts
type CartBundle = {
  id: string;
  productId: string;
  optionId: string;
  variantId: string;
  quantity: number;
  shippingMethod: ShippingMethodId;
  selected: boolean;
  unitPriceAtAdd: number;
  additionalItems: Array<{
    productId: string;
    quantity: number;
    unitPriceAtAdd: number;
  }>;
  addedAt: number;
  updatedAt: number;
};
```

- persist key는 `staygraf-cart`, version은 `1`이다.
- 마지막 수정 후 30일이 지난 묶음은 hydrate 직후 제거한다.
- 동일성 키는 `productId + optionId + variantId + shippingMethod + 정렬된 추가 상품 ID`다.
- 동일성 키가 같으면 본품과 같은 추가 상품의 수량을 합친다.
- 마지막 단일 삭제 스냅샷 한 건과 만료 시각은 메모리 상태로만 보관하고 persist하지 않는다.

## 4. 현재 상품 재검증

저장된 가격을 판매가로 사용하지 않는다. `productId`, `optionId`, `variantId`로 현재 카탈로그 데이터를 찾아 화면과 합계를 계산한다.

| 상태 | 판정 | UI와 선택 처리 |
|---|---|---|
| 정상 | 상품·옵션·규격·배송 사용 가능 | 주문 가능 |
| 가격 변경 | 현재 단가와 `unitPriceAtAdd` 불일치 | 전·후 가격 안내, 선택 유지 |
| 상품/옵션/규격 종료 | 현재 데이터에서 찾을 수 없음 | 구매 불가 표시, 선택 해제 |
| 배송 종료 | 선택 배송이 현재 허용 목록에 없음 | 배송 재선택 요구, 선택 해제 |
| 추가 상품 종료 | 현재 추가 상품 데이터에 없음 | 해당 행 상태 표시, 묶음 선택 해제 |

현재 목업에는 판매 중지 상태가 없지만 판정 타입과 UI 분기 구조는 유지한다. 주문 행동 직전 전체 선택 항목을 다시 resolve하며 유효하지 않으면 진행을 막는다.

## 5. 배송 데이터와 계산

배송 방법 정보는 상품 구매 정책 데이터로 분리한다.

| ID | 표시명 | 비용 | 합계 처리 |
|---|---|---:|---|
| `freight-delivery` | 화물 택배 배송 | 상품별 관리자 고정값 | 선택 상품별 합산 |
| `individual-freight` | 개별 화물 운송 | 착불 | 합계 제외 |
| `pickup` | 직접 수령 | 0원 | 0원 표시 |

- 화물 택배 배송비는 묶음 수량과 무관한 상품별 1회 비용으로 계산한다.
- 주문 요약은 `상품 금액 + 선불 배송비 = 총 주문 금액`을 표시한다.
- 착불 상품이 포함되면 총액 아래 `착불 운송비 별도`를 표시한다.
- 배송 그룹 제목은 표시용이며 실제 합배송을 보장하지 않는 안내를 한 번 제공한다.

## 6. 화면 구조

### 6.1 데스크톱 1024px 이상

```text
헤더
장바구니 제목 · 전체 묶음 수
┌ 배송 그룹 및 상품 목록 ───────────┐  ┌ 주문 요약 sticky ──────┐
│ [그룹 선택] 화물 택배 배송         │  │ 선택 상품 N묶음          │
│ ┌ [선택] 이미지 상품 정보 [수량] ┐ │  │ 상품 금액                 │
│ │ 옵션·규격·단가       [배송변경] │ │  │ 선불 배송비               │
│ │ 추가 상품 행         [삭제]     │ │  │ 총 주문 금액              │
│ └───────────────────────────────┘ │  │ [견적서 만들기]           │
└──────────────────────────────────┘  │ [선택 상품 주문]          │
                                      └─────────────────────────┘
```

- 콘텐츠 shell은 기존 헤더와 같은 최대 1280px 축을 사용한다.
- 목록과 요약은 `minmax(0, 1fr) 344px`, gap 32px이다.
- 요약은 `top: 92px` sticky이며 viewport보다 높아지지 않는다.

### 6.2 태블릿 768~1023px

- 주문 요약을 목록 아래 일반 흐름으로 이동한다.
- 상품 카드의 이미지·정보와 우측 조작축은 유지하되 가용 폭에 맞춰 줄인다.
- 모바일 하단 고정 CTA는 사용하지 않는다.

### 6.3 모바일 767px 이하

- 상품 이미지는 88px, 상품명은 최대 두 줄이다.
- 본품 수량과 묶음 삭제는 상품 정보 아래 조작행으로 이동한다.
- 추가 상품은 이름·단가 행과 수량·삭제 행을 분리한다.
- 배송 변경은 상품 카드 내부 44px 전체폭 컨트롤로 제공한다.
- 하단에는 `선택 N묶음 · 총액`과 `주문하기`를 고정하고 safe area만큼 여백을 예약한다.
- 견적서 버튼과 상세 금액은 본문의 주문 요약에서 제공한다.

## 8. 상호작용과 접근성

- 체크박스는 native input을 사용하고 그룹의 일부만 선택되면 indeterminate를 표시한다.
- 수량은 숫자 입력과 ± 버튼을 함께 제공하며 최소 1이다.
- 배송 선택은 기존 `SelectMenu`를 재사용한다.
- 삭제 아이콘에는 대상 상품명을 포함한 `aria-label`을 제공한다.
- 가격·그룹 이동·삭제 피드백은 `aria-live="polite"`로 전달한다.
- 일괄 삭제 대화상자는 취소에 초기 포커스를 두고 Escape로 닫는다.
- 모든 조작 영역은 최소 44×44px, 인접 조작 간 8px을 유지한다.

## 9. 시각 원칙

- 기존 Pretendard, `--ink`, `--muted`, `--brand`, `--tint`, `--line` 토큰을 사용한다.
- 본품 카드 radius는 4~6px, 무거운 그림자는 사용하지 않는다.
- 추가 상품 종속 영역만 옅은 중립 배경으로 구분한다.
- 위험 동작은 상시 빨간색으로 과장하지 않고 hover·focus와 확인 문구로 대상을 명확히 한다.
- 삭제·그룹 이동은 opacity/translate 160~200ms만 사용하고 크기 애니메이션은 피한다.

## 11. 구현 순서

1. 상품 구매·배송 공통 데이터 분리
2. Zustand persist 장바구니 상태와 단위 테스트
3. 상품 상세 전체 CTA 연결과 헤더 배지
4. `/cart` 배송 그룹·상품 카드·주문 요약 구현
5. 삭제 실행 취소·일괄 삭제 확인·가격 상태 피드백
6. 모바일 하단 영역과 반응형 CSS
7. E2E, 접근성, overflow와 품질 명령 검증

## 12. 검증 시나리오

- 상품 상세에서 추가 상품과 배송을 선택해 장바구니에 담는다.
- 같은 구성은 수량이 합쳐지고 다른 추가 상품 조합은 별도 묶음이 된다.
- 헤더 배지와 장바구니 묶음 수가 일치한다.
- 상품 배송 변경 시 선택을 유지한 채 그룹이 이동한다.
- 그룹 전체 선택과 개별 선택이 요약 금액에 반영된다.
- 추가 상품과 묶음 삭제·실행 취소가 정확하다.
- 착불은 합계에서 제외되고 직접 수령은 0원이다.
- 320~1440px에서 overflow 없이 조작할 수 있다.
- 새로고침 후 장바구니가 복원된다.
