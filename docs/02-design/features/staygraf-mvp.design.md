## 1. Overview

이 문서는 STAYGRAF MVP의 사용자 화면을 실제 브라우저에서 검증하기 위한 프론트엔드 설계를 정의한다. 제품 범위와 커머스 정책의 원본은 Plan 문서이며, 여기서는 화면 구조, 상태 책임, 컴포넌트 경계, 샘플 데이터 규모와 검증 순서를 구체화한다.

현재 단계에서는 ERD, API, 백엔드와 관리자 구현 구조를 확정하지 않는다. 승인된 사용자 UI에서 실제로 요구되는 데이터를 확인한 뒤 별도 설계한다.

### 1.1 설계 원칙

- `GRAF`와 `SHOP`을 동등한 최상위 탐색 경로로 제공한다.
- 홈은 GRAF를 시각적으로 우선하되 상품 카테고리와 검색에 즉시 접근할 수 있게 한다.
- 전문 거래 정보를 감추지 않고 일반 사용자에게는 용어와 환산 맥락을 제공한다.
- 옵션 변경 시 이미지, 가격, 규격과 구매 조건이 하나의 상태로 함께 변경된다.
- 정적인 목업이 아니라 브라우저에서 작동하는 화면으로 UX를 승인한다.
- 확정되지 않은 데이터 구조와 미래 정책은 선구현하지 않는다.

## 2. 사용자 여정

### 2.1 GRAF 중심 탐색

1. 홈에서 공간 이미지와 GRAF를 탐색한다.
2. GRAF 상세에서 공간, 시공업체와 연결 상품을 확인한다.
3. 연결 상품의 상세로 이동한다.
4. 옵션별 이미지·규격·가격 또는 가격 문의 여부를 확인한다.
5. 구매 가능 상품은 수량을 결정해 장바구니에 담고, 가격 문의 상품은 로그인 후 문의한다.

### 2.2 SHOP 중심 탐색

1. 헤더, 카테고리 또는 검색으로 상품 목록에 진입한다.
2. 카테고리별 필터와 정렬로 상품을 좁힌다.
3. 목록에서 상품과 대표 옵션 이미지를 비교한다.
4. 상품 상세에서 옵션과 구매 조건을 검토한다.
5. 구매 가능 상품을 장바구니에 담거나 가격 문의를 접수한다.

### 2.3 장바구니·견적·주문

1. 비회원도 상품을 장바구니에 담는다.
2. 각 상품에서 가능한 배송 방식 하나를 선택한다.
3. 장바구니는 선택한 배송 방식별로 상품을 나눠 보여준다.
4. 사용자는 배송 그룹을 넘나들며 주문 또는 견적 대상 상품을 선택한다.
5. 주문·견적 단계에서 로그인한다.
6. 선택 상품을 한 번에 모의 결제하거나 구매 전 견적서를 생성한다.
7. 주문 한 건 안에서 여러 배송 묶음을 확인한다.

### 3.3 첫 UI 검증 범위

첫 구현은 다음 연결만 완결한다.

`홈 → GRAF 상세 → 상품 상세 또는 상품 목록 → 장바구니`

이 범위에서 헤더 탐색, 옵션 전환, 이미지 전환, 가격 방식, 타일 계산기, 수량 반영, 배송 방식 선택과 장바구니 그룹 변경을 실제로 동작시킨다.

## 4. 상품 목록과 필터

### 4.1 검증 규모

- 시각적 완성도가 높은 대표 상품은 약 10~15개를 준비한다.
- 필터 검증용 메타데이터는 100~120개 상품으로 시작하고 300개까지 확장 가능하게 구성한다.
- 초기 120개 기준 분배안은 타일·빅슬랩 60, 수전 30, 조명 30이다.
- 옵션은 전체 약 300~450개 규모를 가정한다.
- 실제 브랜드와 제품을 조사해 속성과 표현 방식을 참고하되 이름·로고·이미지는 복제하지 않는다.

### 4.2 필터 동작

- 검색어, 카테고리, 필터와 정렬은 URL Search Params에 직렬화한다.
- 같은 필터 그룹 안에서는 OR, 서로 다른 그룹 사이는 AND로 조합한다.
- 각 선택지는 현재 조건에서의 결과 개수를 표시할 수 있어야 한다.
- 적용된 조건은 칩으로 보여주고 개별 해제와 전체 초기화를 제공한다.
- 데스크톱은 필터 패널, 모바일은 필터 시트 사용을 우선 검토한다.
- 뒤로 가기, 새로고침과 공유 URL에서 동일한 목록 상태를 복원한다.
- 옵션 속성으로 일치한 결과는 해당 옵션의 대표 이미지와 가격을 우선 표시한다.

### 4.3 속성 계층

`Brand > Collection > Product > Option` 계층을 사용한다. Collection은 제조사가 같은 디자인·소재·컨셉으로 묶은 제품군이며, 데이터가 충분한 경우 검색과 필터에 사용하는 정식 속성이다. 최종 필터 항목과 노출 순서는 실제 샘플 분석과 UI 대안 승인 후 확정한다.

## 5. 상품 상세 상태

### 5.1 공통

- 상품 갤러리, 상품명, 브랜드·컬렉션, 가격 방식, 판매 상태와 배송 조건을 제공한다.
- 옵션 선택은 이미지, 가격, 규격, 포장 정보와 계산 기준을 동시에 갱신한다.
- 구매 가능, 가격 문의, 품절과 판매 중지의 주 행동을 명확하게 구분한다.

### 5.2 타일·빅슬랩 계산기

- 입력: 필요한 시공 면적
- 기준: 선택 옵션의 포장당 시공 가능 면적
- 계산: `ceil(필요 면적 / 포장당 시공 면적)`
- 출력: 이론상 최소 구매 수량과 실제 구매 가능 면적
- 계산 결과를 수량에 적용하되 자동으로 장바구니에 담지 않는다.
- 재단·파손으로 추가 수량이 필요할 수 있다는 일반 안내를 함께 제공한다.

## 6. 장바구니 설계

- 비회원 장바구니만 Zustand persist로 브라우저에 저장한다.
- 상품별 가능한 배송 방식 중 사용자가 하나를 선택한다.
- 선택한 배송 방식이 바뀌면 화면의 그룹 배치도 즉시 갱신한다.
- 그룹은 표시와 검토를 위한 구분이며 실제 합배송을 보장하지 않는다고 안내한다.
- 사용자는 서로 다른 그룹에서 상품을 선택해 한 번에 주문하거나 견적을 생성할 수 있다.
- 선택하지 않은 상품은 장바구니에 유지한다.
- 로그인 장바구니 병합 정책은 로그인 화면 UX와 백엔드 설계 시 별도로 승인한다.

## 7. 프론트엔드 아키텍처

### 7.1 저장소

```text
staygraf/
├── apps/
│   └── web/
├── docs/
├── AGENTS.md
├── package.json
├── pnpm-lock.yaml
└── pnpm-workspace.yaml
```

- pnpm 기반의 가벼운 workspace를 사용한다.
- 초기에는 `apps/web`만 생성한다.
- 관리자는 승인된 구현 시점에 `apps/admin`으로 분리한다.
- 공용 패키지는 실제 공유 코드가 생긴 뒤 추가한다.

### 7.2 기술 선택

| 영역 | 결정 | 적용 원칙 |
|---|---|---|
| 프레임워크 | Next.js App Router | Server Component 기본, 최소 Client 경계 |
| 언어 | TypeScript strict | 입력 검증과 타입 좁히기 우선 |
| 스타일 | Tailwind CSS | 의미 기반 토큰, 최소 전역 CSS |
| UI 기반 | shadcn/ui 선택 사용 | 범용 접근성 요소만 사용, 전용 UI는 직접 설계 |
| URL 상태 | Search Params | 검색·필터·정렬 |
| 로컬 상태 | React state | 옵션·갤러리·계산기 |
| 지속 상태 | Zustand persist | 비회원 장바구니만 |
| 폼 | React Hook Form + Zod | 로그인·문의·견적·주문 |
| 서버 상태 | 미도입 | 백엔드 확정 후 재검토 |

### 7.3 컴포넌트 경계

범용 UI 후보는 Button, Input, Dialog, Sheet, Tabs, Select, Checkbox와 Form Field다. 도메인 전용 컴포넌트는 다음 책임을 독립적으로 가진다.

- GRAF 카드·갤러리·연결 상품 영역
- 상품 카드·옵션 썸네일·가격 표시
- 상품 갤러리·옵션 선택기·규격 표
- 필터 패널·적용 칩·모바일 필터 시트
- 면적 계산기
- 배송 방식 선택기·배송 그룹 장바구니
- 가격 문의 폼·견적서 미리보기

공용화는 예상이 아니라 실제 두 곳 이상의 반복과 안정된 인터페이스를 확인한 뒤 수행한다.

## 8. 시각·이미지 방향

- 브랜드 톤은 전문 자재 정보의 정밀함과 따뜻한 공간 편집 감성을 함께 가져간다.
- 상품 이미지는 중립적이고 프리미엄한 카탈로그 팩샷을 지향한다.
- GRAF 이미지는 현실적인 재질과 자연광을 가진 건축·인테리어 편집 이미지로 구성한다.
- 고품질 대표 이미지 10~15개를 먼저 제작해 아트 디렉션과 화면 조화를 승인받는다.
- 이후 승인된 스타일만 확장한다.
- 컬러, 타이포그래피, 간격과 구체적인 레이아웃 토큰은 UI UX Pro Max 기반 대안 비교 후 확정한다.

## 9. 접근성·반응형·성능

- 의미 있는 HTML과 키보드 조작을 기본으로 한다.
- 색상만으로 옵션이나 상태를 표현하지 않는다.
- 터치 대상, 포커스 표시, 텍스트 대비와 상태 알림을 검증한다.
- 모바일과 데스크톱에서 핵심 여정을 각각 검토한다.
- 이미지 크기를 예약해 레이아웃 이동을 줄이고 화면 밖 이미지는 지연 로딩한다.
- 용도와 화면 크기에 맞는 이미지 크기와 품질을 제공한다.

## 10. 품질 전략

- TypeScript strict, ESLint와 Prettier를 기본 품질 게이트로 둔다.
- Vitest와 React Testing Library로 계산식, 상태 변화와 핵심 컴포넌트를 검증한다.
- Playwright로 첫 UI 검증 여정과 이후 주문·문의·견적 여정을 검증한다.
- 핵심 화면에 axe 기반 자동 검사와 수동 키보드 검사를 수행한다.
- 검증 명령은 `lint`, `format:check`, `typecheck`, `test`, `test:e2e`, `build`로 통일한다.
- Storybook은 디자인 토큰과 공유 컴포넌트가 안정된 시점에 도입을 재검토한다.
- MSW는 API 계약 설계 단계까지 보류한다.

## 11. 구현 순서와 품질 게이트

1. 저장소와 pnpm workspace 초기화
2. Next.js·TypeScript·Tailwind 기본 설정
3. ESLint·Prettier·Vitest·Testing Library·Playwright 설정
4. 모든 기본 품질 명령 검증
5. UI UX Pro Max 기반 시각 방향 대안 비교와 승인
6. 고품질 이미지 파일럿 제작과 승인
7. 샘플 상품·옵션·GRAF 데이터 작성
8. 공통 셸과 홈 구현
9. GRAF 상세 구현
10. 상품 목록·필터와 상품 상세 구현
11. 계산기와 비회원 장바구니 구현
12. 브라우저·모바일·접근성 검토와 사용자 승인
13. 나머지 사용자 화면 확장
14. 승인된 화면에서 데이터 요구사항 추출
15. ERD·API·백엔드와 관리자 구조 설계

각 단계는 별도 승인 범위로 다루며 이 문서의 승인만으로 애플리케이션 코드 작성이 자동 승인되지는 않는다.

## 12. 검증 시나리오

- GRAF에서 연결 상품과 업체를 확인하고 상품 상세로 이동한다.
- 필터 URL을 새로고침하거나 공유해도 동일한 결과를 복원한다.
- 옵션 필터 결과의 이미지·가격과 상세 진입 후 선택 옵션이 일치한다.
- 상품 옵션 변경 시 모든 종속 정보가 함께 변경된다.
- 타일 계산 결과를 수량에 적용한 뒤 사용자가 수정하고 장바구니에 담는다.
- 상품의 배송 방식 변경 시 장바구니 그룹이 갱신된다.
- 서로 다른 배송 그룹의 상품을 선택해 하나의 주문으로 진행한다.
- 가격 문의 상품은 구매 버튼 대신 문의 행동을 제공한다.
- 견적 생성 시 대상 제외 상품과 금액 스냅샷 규칙이 지켜진다.

## 13. 미결정 사항

다음 항목은 이후 비교·승인 전까지 확정하지 않는다.

- 구체적인 컬러, 타이포그래피, 간격과 모션 토큰
- GRAF와 상품을 연결하는 최종 인터랙션
- 카테고리별 필터의 최종 항목과 순서
- 페이지네이션, 더 보기 또는 무한 스크롤 방식
- 로그인 후 장바구니 병합 충돌 정책
- Storybook 실제 도입 시점
- API 모킹과 MSW 도입 여부
- 백엔드, 데이터베이스, 인증과 배포 기술
