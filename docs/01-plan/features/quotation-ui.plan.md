> **Summary**: 장바구니의 선택 상품을 국내 일반 견적서 형식의 발행 스냅샷으로 전환하고 이력·인쇄까지 연결한다.

> **Author**: STAYGRAF Team
> **Date**: 2026-08-21
> **Status**: Approved
> **Level**: Starter

## 1. 개요

### 1.1 목적

업체 구매자를 중심으로 로그인 회원이 장바구니에서 선택한 구매 가능 상품을 견적서로 발행할 수 있게 한다. 견적서는 상품·옵션·규격·추가 상품·배송 조건·세금·총액을 발행 시점의 스냅샷으로 보존하고, 일반적인 국내 견적서 형식으로 다시 열람하거나 인쇄·PDF 저장할 수 있어야 한다.

### 1.2 배경

- 타일과 인테리어 자재는 주문 단위, 옵션, 규격, 배송 방식이 상품마다 달라 구매 전 내부 검토 문서가 필요하다.
- 업체 구매자는 장바구니 화면보다 공급자·수신자·세금·견적 조건이 포함된 문서를 요구할 수 있다.
- 일반 회원도 동일 기능을 사용할 수 있으나 회원 유형이나 업체 등급은 이번 범위에서 분리하지 않는다.
- 실제 API와 서버 PDF 생성 전에도 사용자 화면과 발행 흐름을 검증할 수 있게 브라우저 상태로 먼저 구현한다.

## 2. 목표와 성공 기준

### 2.1 핵심 목표

- 로그인 회원이 선택한 장바구니 묶음으로 견적서를 발행한다.
- 발행 전 최신 상품·가격·할인·배송 정책을 재검증한다.
- 발행 시점의 공급자·수신자·품목·가격·세금·배송 조건을 변경 불가능한 스냅샷으로 저장한다.
- 국내에서 통용되는 일반 견적서의 정보 순서와 표 형식을 따른다.
- 발행 이력에서 견적서를 다시 열고 A4 인쇄 또는 브라우저 PDF 저장을 수행한다.

### 2.2 완료 기준

- 장바구니 선택부터 정보 입력, 미리보기, 발행, 이력, 재인쇄까지 한 흐름으로 완료된다.
- 본품·추가 상품·배송비의 합계와 공급가액·부가세가 정확히 일치한다.
- 가격 변경이나 판매 종료를 사용자 동의 없이 조용히 반영하거나 제외하지 않는다.
- 320·390·768·1024·1440px에서 가로 overflow나 핵심 행동 누락이 없다.
- A4 세로 인쇄에서 긴 상품명, 다중 품목, 추가 상품, 혼합 배송이 잘리거나 겹치지 않는다.
- 타입 검사, 린트, 단위 테스트, E2E, 프로덕션 빌드가 통과한다.

## 3. 사용자와 핵심 여정

### 3.1 대상 사용자

- 주 사용자: 현장·자재 구매를 검토하고 내부 결재나 구매 준비 문서가 필요한 업체 구매자
- 허용 사용자: 로그인한 모든 일반 회원
- 제외 정책: 업체별 가격, 회원 등급별 가격, 별도 업체 회원 유형

### 3.2 화면 경로

| 화면 | 경로 | 역할 |
|---|---|---|
| 견적 정보 입력 | `/quotes/new` | 수신자 정보와 선택 상품 요약 확인 |
| 견적서 미리보기 | `/quotes/preview` | 일반 견적서 형식으로 최종 검토 |
| 견적 이력 | `/mypage/quotes` | 발행 견적 목록 확인 |
| 견적 발행본 | `/mypage/quotes/[quoteId]` | 발행 스냅샷 열람·인쇄 |

### 3.3 발행 흐름

1. 장바구니에서 구매 가능한 묶음을 선택한다.
2. 주문 요약 영역의 `선택 상품 견적서 만들기`로 진입한다.
3. 비로그인이면 모의 로그인 후 `/quotes/new`로 복귀한다.
4. 선택 상품·옵션·규격·추가 상품·배송 방식과 현재 가격을 검증한다.
5. 견적명과 수신 정보를 입력한다.
6. `견적서 미리보기`에서 일반 견적서 형식과 최종 합계를 확인한다.
7. 발행 직전 상품 상태와 가격을 다시 검증한다.
8. 변경이 없으면 견적번호와 발행 스냅샷을 생성한다.
9. 발행본 상세로 `replace` 이동해 중복 발행을 막는다.
10. 발행본에서 인쇄·PDF 저장 또는 견적 이력 이동을 제공한다.

### 3.4 핵심 상태 규칙

- 견적서 발행은 장바구니의 수량·선택·상품을 변경하거나 삭제하지 않는다.
- 발행 전에는 현재 가격을 사용하고, 발행 후에는 스냅샷 금액을 유지한다.
- 발행 견적서는 주문·결제·재고 확보를 보장하지 않는다.
- 발행본은 수정하지 않는다.
- 가격 문의·판매 종료·유효하지 않은 옵션은 견적 대상이 될 수 없다.
- 견적 유효기간은 발행일로부터 14일이다.
- 만료 후에도 발행본 열람과 인쇄는 가능하다.

## 5. 견적 정책

### 5.1 견적명

- `견적명 또는 현장명`은 선택 입력이며 최대 50자다.
- 입력 시 발행본과 이력 대표 제목으로 사용한다.
- 미입력 시 문서는 `자재 구매 견적`, 이력은 `{발행일} 자재 구매 견적`을 사용한다.

### 5.2 수신자

| 항목 | 필수 | 기본값 |
|---|:---:|---|
| 수신처(회사명 또는 이름) | O | 없음 |
| 담당자명 | O | 로그인 회원명 |
| 연락처 | O | 로그인 회원 연락처 |
| 이메일 | X | 로그인 회원 이메일 |

- 수신자 사업자등록번호·주소·부서·직급·팩스·배송지는 받지 않는다.
- 이메일이 비어 있으면 발행본에서 해당 행을 숨긴다.

### 5.3 공급자

현재는 단일 모의 설정으로 관리하고 발행 시 스냅샷으로 복사한다.

| 항목 | 모의 값 |
|---|---|
| 상호 | STAYGRAF |
| 사업자등록번호 | 000-00-00000 |
| 대표자 | 미등록 |
| 주소 | 서울특별시 성동구 성수이로 00 |
| 업태 | 도소매업 |
| 종목 | 인테리어 자재 |
| 대표전화 | 02-0000-0000 |
| 이메일 | contact@staygraf.example |

- 공급자 정보의 DB·관리자 관리 여부는 실제 백엔드 설계에서 결정한다.
- 실제 직인, 계좌번호, 개인 담당자 연락처는 포함하지 않는다.

### 5.4 견적번호와 상태

- 형식: `SGQ-YYYYMMDD-영문대문자숫자4자리`
- 미리보기에는 번호 대신 `발행 전`을 표시한다.
- 발행 성공 시에만 번호를 생성하고 기존 이력과 충돌하면 재생성한다.
- 상태는 `유효`, `만료`만 사용하고 `validUntil`로 계산한다.
- 실제 API에서는 서버가 유일한 번호를 생성한다.

### 5.5 보관

- 작성 초안은 회원별 활성 초안 한 건을 `sessionStorage`에 저장한다.
- 새로고침·뒤로가기·같은 탭의 재진입에는 복원한다.
- 발행 성공·로그아웃·탭 종료 시 초안을 제거한다.
- 발행 이력은 실제 API 연결 전까지 브라우저 영구 저장소에 임시 보관한다.
- 프론트에서 1년·최대 개수·자동 삭제 같은 실제 운영 정책을 만들지 않는다.

## 6. 일반 견적서 발행본

### 6.0 최종 표현 원칙

- 발행본은 `한국 B2B 모던 실무형`을 기준으로 하며 A4 세로와 8열 품목 표를 유지한다.
- 문서 상단은 작은 단색 `STAYGRAF` 워드마크, 중앙 제목, 우측 견적 메타로 균형을 맞춘다.
- 수신·공급 정보는 세로쓰기 라벨을 사용하지 않고 `받는 분`, `공급자` 가로 제목의 2열 정보 블록으로 구성한다.
- 견적금액은 두꺼운 사각 박스 대신 한글 금액과 숫자 금액을 함께 읽는 얇은 총액 밴드로 표현한다.
- 화면과 인쇄는 같은 데이터를 사용하되 899px 이하 화면은 읽기 쉬운 카드형으로 재배치하고, 인쇄는 A4 표를 유지한다.

### 6.1 문서 순서

1. `견 적 서` 제목
2. 견적번호·작성일자·유효기간
3. 수신자 정보와 공급자 정보
4. 한글 금액과 숫자 총 견적금액
5. `견적 내역` 제목
6. 품목 표
7. 정상 상품금액·할인·배송비·공급가액·부가세·견적 합계
8. 배송 및 견적 조건

### 6.2 품목 표

```text
No. | 품명 | 규격·옵션 | 수량 | 단위 | 단가(VAT 포함) | 공급가액 | 세액
```

- 품목표 우측 상단에 `(단위: 원)`을 한 번 표시하고 금액 셀에는 숫자만 표기한다.
- 추가 상품은 품명 앞의 `└` 형태 장식선과 들여쓰기로 본품 종속 관계를 표시한다.

- 문서는 A4 세로형이다.
- 품명은 `[브랜드] 상품명`을 한 줄에서 시작하고 자연 줄바꿈한다.
- 품명에는 말줄임표나 line-clamp를 사용하지 않는다.
- 컬렉션은 독립 항목으로 표시하지 않으며 필요하면 상품명 데이터에 포함한다.
- 규격·옵션 셀은 최대 2줄을 기본으로 하며 `아이보리 · 600×600mm`, `4장/BOX · 1.44㎡/BOX`처럼 반복 라벨 없이 압축한다. 총 주문 면적은 수량이 2 이상일 때만 추가한다.
- 추가 상품의 규격·옵션 셀에는 실제 선택 속성만 표시하고, 속성이 없으면 비워 둔다. `본품 N번 추가 상품` 같은 관계 설명은 넣지 않는다.
- 로스율과 권장 주문 수량은 계산기 안내값이므로 발행 견적서에 포함하지 않는다.
- 브랜드 배지, 상품 이미지, 컬렉션 전용 행은 사용하지 않는다.
- 본품 번호가 `1`이면 추가 상품은 `1-1`, `1-2`로 표시한다.
- 추가 상품은 본품과 독립된 단가·수량·공급가액·세액을 가진다.

### 6.3 배송 표기

- 배송 그룹 구분 행은 품목 표 내부에 넣지 않는다. 표 아래 배송 조건에는 배송 방식과 `선불`, `착불 별도`, `배송비 0원`만 표시한다.
- 품목 순번은 품목 표 안에서만 사용하며 배송 조건에 반복하지 않는다.
- 화물 택배 배송의 확정 선불 금액은 독립 비용 행이며 합계에 포함한다.
- 배송비 행의 번호는 `-`, 품명은 `화물 택배 배송비`, 단위는 `건`으로 표시한다.
- 개별 화물 운송은 `착불 별도`로 표시하고 합계에서 제외한다.
- 직접 수령은 배송비 행 없이 `0원` 조건으로 표시한다.
- 합배송을 보장하지 않는다는 현재 장바구니 정책을 유지한다.

### 6.4 할인 표기

- 관리자 데이터는 `정상가`와 선택 `할인가`를 저장하고 할인액·할인율은 계산한다.
- 품목 표의 적용 단가는 실제 계산에 사용된 할인가를 표시한다.
- 할인 상품이 있으면 하단에 정상 상품금액과 전체 상품 할인액을 한 번 표시한다.
- 할인 상품이 없으면 정상가·할인 행을 숨긴다.
- 쿠폰, 회원 등급 할인, 업체별 가격은 포함하지 않는다.
- 할인액이 있을 때만 첫 합계 항목을 `정상 상품금액`으로 표기하고, 할인이 없으면 `상품 금액`으로 표기한다.

### 6.5 견적 조건

- 견적 유효기간은 발행일로부터 14일이다.
- 견적서는 주문 확정 또는 재고 확보 문서가 아니다.
- 상품·할인·가격은 발행 시점을 기준으로 한다.
- 착불 운송비는 견적 합계에 포함되지 않는다.
- 납품기한·결제조건은 정책이 없으므로 임의로 표시하지 않는다.

### 6.6 인쇄와 긴 문서

- 데스크톱 미리보기는 실제 A4 폭 `210mm`와 인쇄 여백 12mm를 맞춰 화면과 출력의 줄바꿈 차이를 줄인다.
- 본문·표·조건·푸터는 인쇄 시 9pt 미만으로 축소하지 않는다.
- 긴 상품명은 2~3줄 자연 줄바꿈하며 말줄임표를 사용하지 않는다.
- 표 머리글은 다음 페이지에 반복하되 첫 페이지에 견적번호·수신처를 중복 출력하는 문맥 행은 넣지 않는다.
- 품목이 많으면 2페이지 이상으로 자연스럽게 출력하며 한 페이지에 맞추려고 글자를 축소하지 않는다.

## 7. 가격 계산

### 7.1 품목 계산

```text
품목 총액 = 적용 단가(VAT 포함) × 수량
공급가액 = round(품목 총액 ÷ 1.1)
부가세 = 품목 총액 - 공급가액
```

- 단가를 공급가액으로 먼저 나눈 뒤 수량을 곱하지 않는다.
- 본품·추가 상품·선불 배송비를 각각 독립 행으로 계산한다.
- 전체 공급가액은 행별 공급가액 합계, 전체 부가세는 행별 부가세 합계다.
- 견적 합계는 전체 공급가액과 부가세의 합과 정확히 일치해야 한다.
- 모든 금액은 원화 정수와 천 단위 쉼표를 사용한다.
- 최종 합계는 한글 금액과 숫자 금액을 함께 표시한다.

### 7.2 변경 재검증

- 정보 입력 진입, 미리보기 진입, 최종 발행에서 현재 카탈로그를 재검증한다.
- 가격 변경은 최신 가격으로 갱신하되 발행을 중단하고 다시 확인하게 한다.
- 미리보기에는 변경 품목 수, 이전·현재 단가, 이전·현재 합계와 차이를 표시한다.
- 발행본에는 최종 적용 가격만 표시한다.
- 판매 종료·옵션 종료는 자동 제외하지 않는다.
- 사용자가 `구매 불가 상품 제외하고 계속`을 명시적으로 선택한 경우에만 제거한다.
- 배송 종료는 견적 화면에서 임의 변경하지 않고 장바구니 수정을 요구한다.
- 추가 상품 종료는 해당 추가 상품만 명시적으로 제외할 수 있다.

## 8. 화면과 반응형

### 8.1 정보 입력

- 기존 장바구니·주문서와 같은 1280px shell과 Pretendard를 사용한다.
- 데스크톱은 수신 정보 본문과 선택 상품 sticky 요약의 2열이다.
- 모바일은 한 열이며 하단에 `견적서 미리보기` CTA를 고정한다.
- 상품 구성 변경은 제공하지 않고 `장바구니에서 수정`으로 이동한다.
- 2단계 진행 표시 `정보 입력 → 검토 및 발행`을 제공한다.
- label은 항상 보이고 오류는 blur 시 해당 필드 아래에 표시한다.

### 8.2 미리보기·발행본

- 독립 페이지이며 모달로 만들지 않는다.
- 입력·목록은 STAYGRAF 커머스 UI를 따르고 실제 문서는 국내 일반 견적서 형식을 따른다.
- 데스크톱은 흰색 A4 폭의 연속 문서로 표시한다.
- 모바일은 같은 정보 순서를 유지하되 품목 표를 세로 카드로 변환한다.
- 정확한 페이지 분할은 시스템 인쇄 미리보기에서 확인한다.
- 발행 후에는 수정·발행 버튼을 제거하고 인쇄·이력 행동을 제공한다.

### 8.3 이력

- `/mypage/quotes`에 견적번호·견적명·수신처·발행일·유효기간·상태·견적 합계를 표시한다.
- 데스크톱은 표, 모바일은 카드다.
- 행 또는 카드 전체로 발행본에 이동한다.
- 최소 마이페이지 셸만 구성하고 프로필·주문·좋아요 기능은 만들지 않는다.

### 8.4 시각·접근성

- 기존 `ink`, `muted`, `brand`, `tint`, `line` 토큰을 사용한다.
- 녹색은 주요 CTA, 포커스, 현재 단계에만 사용한다.
- 문서에는 불필요한 배지·그림자·큰 에디토리얼 제목을 사용하지 않는다.
- 화면 본문은 14~16px, 문서 출력은 9~10pt 아래로 내리지 않는다.
- 조작 영역은 최소 44×44px, 인접 조작은 8px 이상 간격을 둔다.
- 가격 변경·오류는 색상 외에 텍스트와 아이콘으로 구분한다.
- 상태 안내는 `role="alert"` 또는 `aria-live`로 전달한다.
- 단계 전환은 opacity·translate 160~200ms만 사용하고 reduced-motion을 지원한다.

## 9. 인쇄·PDF

- `@page`로 A4 portrait와 약 12~15mm 여백을 지정한다.
- 인쇄에서는 사이트 헤더·버튼·알림·모바일 고정 CTA를 숨긴다.
- 표 열 제목은 페이지마다 반복한다.
- 품목 행, 합계, 견적 조건은 가능한 한 페이지 내부 분리를 피한다.
- 한 묶음이 한 페이지보다 길면 추가 상품 행 사이에서만 분리한다.
- 합계와 견적 조건은 마지막 페이지에만 표시한다.
- 두 번째 페이지부터 반복되는 표 머리글에 견적번호와 수신처를 함께 제공한다.
- 브라우저별 지원 차이가 있는 사용자 정의 `1 / N` 페이지 번호는 보장하지 않는다.
- 데스크톱·Android는 시스템 인쇄의 PDF 저장을 사용한다.
- iPhone은 공유·파일 저장 절차를 인접 도움말로 안내한다.
- 출력 전 로컬 Pretendard 로드를 완료한다.

## 10. 상태와 저장 경계

### 10.1 초안

```ts
type QuotationDraft = {
  id: string;
  memberId: string;
  selectedBundleIds: string[];
  title: string;
  recipient: {
    name: string;
    managerName: string;
    phone: string;
    email: string;
  };
  step: "form" | "preview";
  cartFingerprint: string;
  updatedAt: number;
};
```

### 10.2 발행본

```ts
type QuotationSnapshot = {
  id: string;
  quotationNumber: string;
  memberId: string;
  title: string;
  issuedAt: number;
  validUntil: number;
  issuer: IssuerSnapshot;
  recipient: RecipientSnapshot;
  lines: QuotationLineSnapshot[];
  shippingGroups: ShippingGroupSnapshot[];
  regularProductTotal: number;
  discountTotal: number;
  productTotal: number;
  prepaidShippingTotal: number;
  supplyTotal: number;
  vatTotal: number;
  quotationTotal: number;
  hasCollectShipping: boolean;
  terms: string[];
  version: 1;
};
```

### 10.3 책임 분리

| 모듈 | 책임 |
|---|---|
| `quotation-draft-store` | 작성 중 초안과 현재 단계 |
| `quotation-repository` | 발행본 저장·목록·단건 조회 |
| `quotation-service` | 장바구니 재검증·계산·번호 생성·발행 |

- 현재는 브라우저 repository를 사용한다.
- UI 컴포넌트는 `localStorage`를 직접 호출하지 않는다.
- 실제 API 연결 후 repository를 교체한다.
- API 발행 요청에는 선택 묶음 ID·견적명·수신자·중복 방지 키만 전송한다.
- 실제 서버는 현재 가격, 세금, 배송, 번호, 발행 시각, 공급자 정보와 권한을 검증한다.
- 동일 발행 요청은 기존 발행본을 반환할 수 있게 중복 방지 키를 사용한다.
