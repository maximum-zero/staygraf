## 1. Overview

### 1.1 Purpose

전문 인테리어 업체가 규격과 거래 조건을 정확하게 좁혀 찾을 수 있으면서도, 일반 사용자가 전문 지식 없이 이미지와 익숙한 용어로 상품을 탐색할 수 있는 한국형 이커머스 상품 목록·상세 경험을 설계하고 구현한다.

### 1.2 Background

인테리어 자재는 카테고리와 제품마다 규격, 판매 단위, 포장, 옵션별 가격과 배송 조건이 다르다. 모든 정보를 목록에 노출하면 탐색이 복잡해지고, 정보를 감추면 업체의 구매 판단이 어려워진다. 목록은 빠른 탐색과 비교에 집중하고 상세는 정확한 구매 판단을 담당하도록 역할을 분리한다.

초기 100~120개, 이후 300개 상품까지 확장할 수 있는 필터 구조를 전제로 한다. 실제 제품의 속성과 거래 방식을 참고하되 브랜드, 상품명, 로고와 이미지를 복제하지 않는다.

## 2. User Intent

- 주요 사용자는 규격·가격·포장·배송 조건을 빠르게 비교하는 인테리어 업체 실무자다.
- 보조 사용자는 이미지와 쉬운 설명으로 적합한 상품을 찾는 셀프 인테리어 사용자다.
- 국내 사용자가 익숙한 카테고리, 필터, 정렬과 모바일 탐색 방식을 사용한다.
- 해외 편집숍식 과도한 여백, 영문 장식과 비대칭 잡지형 레이아웃을 피한다.
- 사용자 화면을 브라우저에서 승인한 뒤 ERD, API, 백엔드와 관리자 구조를 설계한다.
- 관리자의 상품 등록·관리 경험은 사용자 화면 승인 후 별도 계획으로 다룬다.

## 3. Alternatives Explored

### 3.1 A. 상단 필터 칩형

- 필터가 적을 때 간결하고 모바일·데스크톱 구조가 유사하다.
- 전문 속성이 늘어나면 가로 탐색이 길어지고 전체 조건을 파악하기 어렵다.
- GRAF 목록에는 적합하지만 상품 카탈로그의 확장성은 부족하다.

### 3.2 B. 데스크톱 좌측 상시 필터형

- 많은 속성을 한 번에 비교하고 연속으로 변경하기 쉽다.
- 상품 그리드가 좁아지고 일반 사용자에게 복잡한 B2B 자재표처럼 보일 수 있다.
- 모바일에서 완전히 다른 구조가 필요하다.

### 3.3 C. 로컬 카테고리 탐색 + 요청형 필터 — 선택

- 넓은 데스크톱에는 현재 분기를 펼친 좌측 카테고리 레일, 본문에는 현재 2depth 경로와 결과 개수·정렬을 제공한다.
- 헤더 SHOP은 전역 진입, 좌측 레일은 목록 안의 연속 카테고리 전환을 담당한다.
- 필터는 데스크톱 측면 패널과 모바일 바텀시트에서 필요할 때 연다.
- 적용 조건은 목록 위 칩으로 확인하고 개별 해제 또는 전체 초기화한다.
- 상품 카드 영역을 넓게 유지하면서 카테고리별 전문 필터를 수용한다.
- 한국 이커머스에 익숙한 탐색 위계와 전문 자재 필터를 함께 제공한다.

## 4. Goals

### 4.1 Primary Goals

- [ ] `SHOP → 타일 → 타일 또는 빅슬랩` 탐색 구조를 제공한다.
- [ ] 카테고리 진입 후 세 번 이내의 필터 조작으로 원하는 상품군을 좁힐 수 있게 한다.
- [ ] 목록에서 상품 이미지, 이름, 가격과 대표 옵션 이미지를 빠르게 비교할 수 있게 한다.
- [ ] 상세에서 옵션별 미디어, 규격, 포장, 계산과 배송 조건을 일관된 상태로 검토할 수 있게 한다.
- [ ] 검색·카테고리·필터·정렬 상태를 URL로 복원하고 공유할 수 있게 한다.
- [ ] 100~300개 상품과 카테고리별 서로 다른 속성을 수용한다.

### 4.2 Non-Goals

- 관리자 상품 등록·수정 화면과 범용 속성 편집기
- ERD, API, 데이터베이스와 서버 필터 구현
- 실제 결제 플러그인 연동
- 개인화 추천, 최근 본 상품과 저장된 필터
- 상품 비교함, 찜과 빠른 장바구니
- 할인율, 쿠폰과 무료배송 프로모션 정책
- 3D·AR 상품 미리보기

## 5. Scope

### 5.1 Category Structure

```text
SHOP
├── 타일
│   ├── 타일
│   └── 빅슬랩
├── 수전
└── 조명
```

- 상품 목록은 전체 상품 경로 없이 최소 1depth 카테고리로 진입한다.
- 첫 구현과 검증은 `타일` 1depth와 `타일 / 빅슬랩` 2depth를 대상으로 한다.
- 수전과 조명은 승인된 공통 구조를 재사용하되 전용 필터를 별도로 정의한다.

### 5.2 Product List

- 현재 1depth 분기를 자동으로 펼치는 좌측 카테고리 레일과 경로형 2depth 링크
- 결과 개수, 필터 버튼과 정렬
- 적용 조건 칩, 개별 해제와 초기화
- 데스크톱 필터 측면 패널과 모바일 필터 바텀시트
- 로딩, 빈 결과와 오류 상태
- 휴대폰 1열, 중간 화면 2~3열, 데스크톱 4열 상품 그리드
- 브랜드·컬렉션, 상품명과 가격을 제공하는 상품 카드
- 모든 상품에 필수인 옵션 대표 이미지 썸네일을 한 행 최대 다섯 슬롯으로 제공
- 옵션이 여섯 개 이상이면 대표 이미지 네 개와 `+N`을 표시하므로 추가 개수는 최소 `+2`부터 시작
- 상품 커버는 선택값이며 없으면 기본 옵션의 대표 이미지를 목록 기본 이미지로 사용
- 썸네일 선택 시 카드 대표 이미지만 변경하고 목록 가격은 상품 가격 범위를 유지
- 선택한 옵션으로 상세에 진입할 때 옵션 ID를 URL에 전달해 같은 옵션을 초기 선택
- 카드당 최대 하나의 근거 있는 상태 배지

### 5.3 Product Detail

- 상품 갤러리, 브랜드·컬렉션, 상품명과 가격 방식
- 옵션별 이미지, 가격, 규격과 포장 정보의 동기화
- 구매 가능, 가격 문의, 품절과 판매 중지 상태 구분
- 타일·빅슬랩 면적 계산기와 계산 수량 적용
- 상품별 가능한 배송 방식 안내와 선택
- 구매 가능 상품의 장바구니 또는 바로 구매 진입
- 가격 문의 상품의 로그인 후 문의 진입
- GRAF에 연결된 상품이면 관련 공간 탐색 제공

### 5.4 Pricing and Card Policy

- 구매 가능 상품은 동일 가격이면 단일 가격, 옵션별 차이가 있으면 최소가~최대가로 표시한다.
- 가격 문의는 상품 단위 정책이며 일반 가격과 같은 정보 위치에 중립적으로 표시한다.
- 품절은 GRAF 연결과 상품 정보는 유지하되 구매 행동을 제공하지 않는다.
- 배송 방식, VAT, BOX 표기와 규격은 목록 카드에 노출하지 않고 상세에서 제공한다.
- `NEW`와 `MD PICK`은 실제 등록일 또는 관리자 추천 근거가 있을 때만 사용하며 카드당 최대 하나만 노출한다.

### 5.5 Filter Behavior

- 검색어, 1·2depth 카테고리, 필터와 정렬을 URL Search Params에 직렬화한다.
- 목록에서 선택한 옵션으로 상세에 진입하면 `option` Search Param에 옵션 ID를 전달한다.
- 같은 필터 그룹은 OR, 서로 다른 그룹은 AND로 조합한다.
- 옵션 속성으로 일치한 결과는 해당 옵션 대표 이미지를 우선 표시한다.
- 필터 패널을 닫아도 적용 조건과 결과 개수를 목록에서 확인할 수 있어야 한다.
- 구체적인 타일·빅슬랩 필터 항목과 순서는 실제 제품 속성 분석 후 Design 단계에서 승인한다.
- 페이지네이션, 더 보기 또는 무한 스크롤은 실제 목록 UI와 성능을 확인한 뒤 결정한다.

## 6. YAGNI Review

### 6.1 Must Have

- 1·2depth 카테고리 레일, 요청형 필터, 정렬과 URL 상태
- 적용 조건, 결과 개수, 초기화와 빈 결과
- 옵션 이미지 비교가 가능한 상품 카드
- 가격 방식과 판매 상태 구분
- 반응형 필터 패널·시트와 상품 그리드
- 상품 상세의 옵션·규격·포장·계산·배송 상태

### 6.2 Nice to Have

- 실제 데이터가 준비된 필터 선택지별 예상 결과 개수
- 데이터 근거가 있는 `NEW` 또는 `MD PICK` 배지
- 선택지가 매우 많은 필터 그룹 내부 검색

### 6.3 Won't Do in This Scope

- 찜, 비교, 최근 본 상품, 개인화와 빠른 구매
- 운영 근거가 없는 베스트·할인·무료배송 배지
- 저장된 필터와 고급 검색 문법
- 목록 로딩 방식 선확정

## 7. Functional Requirements

- 사용자는 헤더와 홈 카테고리에서 최소 1depth 상품 목록으로 이동한다.
- 사용자는 2depth를 전환하고 필터와 정렬을 적용·해제·초기화한다.
- 사용자는 새로고침, 뒤로 가기와 공유 URL에서 동일한 목록 상태를 확인한다.
- 사용자는 옵션 썸네일로 대표 이미지를 비교하고 상품 상세로 이동한다.
- 사용자는 상세에서 옵션을 선택해 모든 종속 정보를 함께 변경한다.
- 사용자는 면적 계산 결과를 구매 수량에 적용하되 직접 수정할 수 있다.
- 사용자는 상품이 허용하는 배송 방식 중 하나를 선택한다.
- 사용자는 상품 상태에 따라 장바구니·구매 또는 가격 문의로 이동한다.

## 8. Non-Functional Requirements

- 320~539px 1열, 540~767px 2열, 768~1023px 3열, 1024px 이상 4열의 탐색 구조가 깨지지 않아야 한다.
- 좌측 카테고리 레일은 1240px 이상에서만 제공하고 그보다 좁은 화면은 헤더 탐색을 사용한다.
- 모든 조작 요소는 키보드로 접근 가능하고 모바일 터치 대상은 최소 44px을 지향한다.
- 필터 시트와 패널은 포커스 이동·복귀, Escape 닫기와 배경 스크롤 제어를 제공한다.
- 이미지 공간을 예약하고 화면 밖 이미지를 지연 로딩해 레이아웃 이동을 줄인다.
- 의미 있는 전환은 150~300ms 범위에서 제공하고 `prefers-reduced-motion`을 지원한다.
- 선택 상태를 색상만으로 표현하지 않는다.
- 실제 상품 속성 수가 늘어도 카드 컴포넌트와 URL 상태 모델이 카테고리에 종속되지 않아야 한다.

## 9. Success Criteria

- [ ] 카테고리 진입 후 세 번 이내의 필터 조작으로 목표 상품군을 좁힐 수 있다.
- [ ] 목록 카드에서 옵션 이미지를 변경해도 상품 가격 범위와 상품 정체성이 유지된다.
- [ ] 필터 URL을 새로고침하거나 공유해도 같은 결과가 복원된다.
- [ ] 타일·빅슬랩, 수전과 조명이 공통 목록 틀과 각자의 전용 필터를 사용한다.
- [ ] 모바일에서 필터, 정렬, 상품 카드와 상세 구매 행동을 완료할 수 있다.
- [ ] 판매 상태와 가격 방식에 맞지 않는 구매 행동이 노출되지 않는다.
- [ ] lint, typecheck, unit, E2E와 production build 품질 게이트를 통과한다.
- [ ] 실제 브라우저 화면을 사용자가 검토하고 승인한다.

## 10. Risks & Mitigations

| Risk | Impact | Probability | Mitigation |
|---|---|---|---|
| 카테고리별 속성 차이가 공통 필터를 복잡하게 함 | High | High | 공통 상태 모델과 카테고리별 필터 정의를 분리한다. |
| 전문 정보가 목록 카드에 과도하게 노출됨 | High | Medium | 카드 정보는 이미지·이름·가격·대표 옵션으로 제한한다. |
| 옵션 필터 결과와 대표 이미지가 모순됨 | High | Medium | 일치 옵션 ID를 URL·목록·상세 진입 상태에 함께 전달한다. |
| 필터 패널이 모바일 탐색을 막음 | Medium | Medium | 바텀시트 포커스·스크롤·뒤로 가기 동작을 E2E로 검증한다. |
| 샘플 데이터가 적어 확장성이 검증되지 않음 | High | Medium | 시각 자산과 별개로 100~120개 메타데이터를 생성해 검증한다. |
| 미확정 로딩 방식을 선구현함 | Medium | Low | 실제 목록 성능 확인 전 페이지 방식은 결정하지 않는다. |

## 11. Architecture Considerations

- Next.js App Router의 최소 Client Component 경계를 유지한다.
- 카테고리·필터·정렬은 URL Search Params를 단일 기준으로 사용한다.
- 옵션 선택과 갤러리 같은 일시 상태는 React local state로 관리한다.
- 상품 카드, 가격 표시, 옵션 썸네일과 필터 정의를 독립된 도메인 컴포넌트로 구성한다.
- 실제 API 전에는 승인된 샘플 데이터와 프론트 필터 로직으로 화면을 검증한다.
- 서버 상태와 MSW는 API 계약 단계까지 도입하지 않는다.
- Storybook은 공통 컴포넌트와 디자인 토큰이 안정된 뒤 재검토한다.

## 12. Delivery Order

1. 실제 타일·빅슬랩 상품 속성 분석
2. 필터 항목과 목록 정보 위계 대안 승인
3. 상품 목록·필터 화면 구현과 반응형 검토 — 완료
4. 상품 상세 정보 구조와 옵션 인터랙션 승인
5. 상품 상세·계산기 구현과 반응형 검토
6. 수전·조명 필터 정의와 공통 구조 확장
7. 전체 접근성·상태·성능 검수
8. 승인된 화면에서 ERD·API·관리자 요구사항 추출

## 13. Backlog

- GRAF 목록 필터를 상품 목록과 같은 요청형 필터 패널 구조로 통일할지 재검토한다.
- 상품 목록 로딩 방식은 실제 데이터와 UI 성능 확인 후 결정한다.
- 업체 프로필, 검색과 상품 추천 정책은 별도 기능 계획에서 다룬다.
