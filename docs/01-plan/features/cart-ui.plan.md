# 장바구니 UI 계획서

> **Summary**: 상품 상세의 구매 구성을 비회원 장바구니에 보관하고 배송 방식별로 검토·선택하는 경험

## 1. 사용자 의도

전문 자재 상품의 본품, 옵션, 추가 상품과 배송 조건을 잃지 않고 장바구니에서 다시 검토할 수 있어야 한다. 일반 사용자와 업체 구매자 모두 배송 방식이 다른 상품을 한 화면에서 비교하고, 원하는 상품만 한 번에 주문하거나 견적 대상으로 선택할 수 있어야 한다.

이 단계는 실제 백엔드와 결제를 연결하지 않는다. 상품 상세부터 장바구니까지의 사용자 화면과 브라우저 상태를 완성해 이후 주문서·견적서 설계의 기준으로 사용한다.

## 2. 검토한 대안

### 2.1 배송 방식별 장바구니 분리

- 장점: 배송 조건이 즉시 보이고 전문 자재 구매에 적합하다.
- 단점: 같은 상품이 배송 변경 시 화면에서 이동한다.
- 결정: 표시 그룹으로 채택하되 합배송을 의미하지 않는다고 안내한다.

### 2.2 상품 목록 하나에 배송 배지만 표시

- 장점: 화면이 단순하다.
- 단점: 배송 방식별 비용과 주문 조건을 비교하기 어렵다.
- 결정: 핵심 문제를 해결하지 못해 제외한다.

### 2.3 배송 그룹마다 별도 결제

- 장점: 주문 구조가 단순하다.
- 단점: 사용자가 여러 번 결제해야 하고 승인된 단일 주문 흐름과 충돌한다.
- 결정: 제외한다. 여러 그룹을 선택해 한 번에 다음 단계로 이동한다.

## 3. YAGNI 검토

### Must Have

- 상품 상세에서 실제 장바구니 저장
- 비회원 브라우저 보관과 헤더 개수
- 배송 방식별 표시 그룹
- 그룹 및 상품 묶음 선택
- 본품·추가 상품 수량 변경과 삭제
- 상품별 배송 방식 변경
- 선택 상품 주문·견적 진입
- 가격·판매 상태 변경 안내 구조
- 모바일 고정 주문 영역과 데스크톱 주문 요약

### Nice to Have

- 단건 삭제 후 5초 실행 취소
- 장바구니 빈 상태에서 쇼핑 이동
- 절제된 그룹 이동·삭제 모션

### Won't Do

- 서버 장바구니와 로그인 후 병합
- 쿠폰, 적립금, 프로모션
- 합배송비 자동 계산
- 실제 주문서, 결제와 견적서 발행
- 품절 상품 자동 대체
- 여러 삭제 기록을 쌓는 실행 취소 이력

## 4. 기능 범위

### 4.1 장바구니 묶음

- 본품과 선택한 추가 상품은 하나의 장바구니 묶음이다.
- 추가 상품은 본품에 종속되며 별도 선택 체크박스를 갖지 않는다.
- 추가 상품은 각자 수량을 바꾸거나 삭제할 수 있다.
- 본품 삭제 시 종속 추가 상품도 함께 삭제한다.
- 같은 상품·옵션·규격·배송 방식과 같은 추가 상품 종류 조합이면 기존 묶음에 수량을 합친다.
- 추가 상품 종류 조합이 다르면 별도 묶음으로 저장한다.

### 4.2 저장과 선택

- 비회원 장바구니는 Zustand persist로 브라우저에 저장한다.
- 마지막 수정 시점부터 30일이 지나면 만료 처리한다.
- 선택 상태와 수량·배송 방식도 새로고침 후 복원한다.
- 배송 그룹 전체 선택과 상품 묶음별 선택을 모두 제공한다.
- 주문하지 않은 상품은 장바구니에 유지한다.

### 4.3 배송 방식과 배송비

- 배송 방식은 상품 단위로 선택하고 변경한다.
- `화물 택배 배송`: 관리자가 상품에 입력한 고정 배송비를 선택 상품 합계에 포함한다.
- `개별 화물 운송`: 항상 착불이며 합계에서 제외하고 `착불 · 운송비 현장 결제`로 표시한다.
- `직접 수령`: 배송비 0원으로 표시한다.
- 같은 배송 방식 그룹도 실제 합배송을 보장하지 않는다.
- 화물 택배 배송비는 MVP에서 상품별로 합산한다.

### 4.4 가격과 판매 상태 변경

- 장바구니는 현재 판매 정보를 기준으로 표시한다.
- 가격이 바뀌면 최신 가격을 적용하고 담을 당시 가격과 변경 내용을 안내하며 선택은 유지한다.
- 주문 행동 시 가격이 다시 바뀌면 진행을 중단하고 갱신된 금액 확인을 요구한다.
- 품절·판매 중지·선택 옵션 종료는 묶음을 보존하되 선택 해제한다.
- 선택 배송 방식이 종료되면 배송 선택을 해제하고 재선택을 요구한다.
- 선택한 추가 상품이 종료되면 상태를 표시하고 묶음을 선택 해제한다.
- 다른 옵션이나 배송 방식으로 자동 대체하지 않는다.

### 4.5 삭제

- 단일 묶음 또는 추가 상품 삭제는 즉시 실행한다.
- 최근 단일 삭제 한 건만 5초 동안 실행 취소할 수 있다.
- 선택 상품 일괄 삭제는 확인 대화상자를 거친다.

### 4.6 주문과 견적 진입

- 서로 다른 배송 그룹의 선택 상품을 한 번에 주문 대상으로 전달한다.
- 주문 진입 시 로그인 요구 안내를 제공하고 실제 주문서는 후속 범위로 둔다.
- 견적서는 장바구니의 선택된 구매 가능 상품으로 시작한다.
- `견적서 만들기`는 별도 견적 정보 입력·미리보기 화면으로 이어지며 로그인 기능은 후속 범위다.
- 발행 전 견적은 최신 가격을 사용한다.
- 발행된 견적은 가격·세금·배송 조건을 고정하고 14일간 유효하다.
- 가격 변경 후 재견적은 새 견적번호로 발행한다.

## 5. 화면 요구사항

- 데스크톱은 배송 그룹별 목록과 320~360px 주문 요약을 나란히 배치한다.
- 모바일은 상품 정보 아래 조작행과 안전 영역을 반영한 하단 고정 주문 영역을 사용한다.
- 데스크톱 본품 조작은 카드 우측, 모바일은 상품 정보 아래에 둔다.
- 추가 상품 조작은 종속된 각 행 안에서 제공한다.
- 배송 변경 시 해당 묶음만 새로운 표시 그룹으로 이동하고 선택 상태는 유지한다.
- 주문 요약은 선택 상품 금액, 선불 배송비, 착불 안내와 총액을 구분한다.
- 빈 장바구니에는 `상품 둘러보기`를 제공한다.

## 6. 비기능 요구사항

- 320, 390, 768, 1024, 1440px에서 가로 스크롤이 없어야 한다.
- 체크박스, 수량, 배송 변경, 삭제와 주요 CTA는 44px 이상의 조작 영역을 가진다.
- 키보드로 선택·수량·배송·삭제·실행 취소를 사용할 수 있어야 한다.
- 상태 변화는 텍스트와 `aria-live`로 알리고 색상에만 의존하지 않는다.
- 그룹 이동과 피드백은 150~200ms로 제한하고 `prefers-reduced-motion`을 지원한다.
- 목업 데이터가 즉시 준비되므로 이 단계에서는 스켈레톤을 사용하지 않는다.

## 8. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 배송 그룹을 합배송으로 오해 | 높음 | 그룹 설명과 상품별 배송비 표시를 유지한다. |
| 저장 가격과 현재 가격 불일치 | 높음 | 식별자와 담을 당시 가격을 저장하고 현재 데이터로 재검증한다. |
| 추가 상품 종속 관계 혼동 | 중간 | 별도 체크박스를 두지 않고 본품 카드 안에 중첩한다. |
| 모바일 고정 영역이 콘텐츠를 가림 | 중간 | safe area와 본문 하단 여백을 함께 예약한다. |
| 브라우저 저장 데이터 구조 변경 | 중간 | persist version과 migration/초기화 경계를 둔다. |

## 9. 아키텍처 고려사항

- Next.js App Router와 TypeScript strict를 유지한다.
- 장바구니 지속 상태는 이미 설치된 Zustand persist만 사용한다.
- 상품·옵션·배송의 현재 정보는 카탈로그 목업 데이터를 신뢰 원본으로 사용한다.
- 지속 상태에는 장바구니 식별자, 선택 구성, 수량, 배송 방식, 담을 당시 가격과 수정 시점을 저장한다.
- UI 컴포넌트는 장바구니 도메인 안에서 먼저 안정화하고 실제 반복이 확인될 때만 공용화한다.
