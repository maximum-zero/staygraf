# 배송지 관리 UI 계획서

> **Summary**: 주문·결제 화면에 회원 배송지 선택·관리와 카카오 우편번호 검색을 추가한다.
>
> **Date**: 2026-08-19
> **Version**: 1.0
> **Status**: Approved
> **Level**: Starter

---

## 1. 배경과 목적

현재 주문서는 수령인과 주소를 매번 직접 입력해야 하며, 저장된 배송지를 선택하거나 주소를 검색할 수 없다. 반복 주문 시 입력 부담을 줄이고 국내 사용자가 익숙한 주소 검색 흐름을 제공하기 위해 배송지 관리 기능을 추가한다.

이번 단계는 실제 회원·주소 API를 연결하기 전 사용자 화면과 브라우저 상태를 완성하는 범위다. 저장 책임을 독립 모듈로 두어 이후 `member_addresses` API로 교체할 수 있게 한다.

## 2. 확정 목표

- 주문서에서 선택된 배송지를 한눈에 확인하고 변경할 수 있다.
- 배송지 목록에서 선택·추가·수정·삭제·기본 배송지 지정을 할 수 있다.
- 공식 카카오 우편번호 검색으로 우편번호와 도로명 주소를 채울 수 있다.
- 주소 검색 서비스를 불러오지 못해도 사용자가 주소를 직접 입력해 주문을 계속할 수 있다.
- 직접 수령 상품만 주문할 때는 배송지 관리 UI를 노출하지 않는다.
- 데스크톱은 모달, 모바일은 바텀시트 형태로 같은 기능을 제공한다.

## 3. 범위

### 3.1 포함

- 주문서 배송 정보 상단의 선택 배송지 요약 카드
- `배송지 변경` 또는 빈 상태의 `배송지 추가` 행동
- 배송지 목록과 기본 배송지 표시
- 배송지 추가·수정 폼
- 배송지 선택, 기본 지정, 삭제
- 카카오 우편번호 공식 스크립트 지연 로딩과 팝업 검색
- 팝업 차단·네트워크 오류 시 재시도와 수동 입력 전환
- 브라우저 `localStorage` 저장, 저장 후 30일 만료
- 현재 로그인한 모의 회원 ID별 데이터 분리
- 주문 초안의 수령인·연락처·우편번호·주소·상세주소와 동기화
- 키보드 포커스 관리, Escape 닫기, 배경 스크롤 잠금, 44px 조작 영역
- 320·390·768·1024·1440px 반응형 검증

### 3.2 제외

- 실제 회원 주소 API와 데이터베이스 연결
- 지도 좌표·건물 위치 저장
- 공동현관 출입방법 같은 별도 배송지 메타데이터
- 카카오톡 공유·카카오 로그인
- 배송 가능 지역 또는 추가 운임 자동 판정

## 4. 정책

### 4.1 배송지 데이터

- 필드: 배송지명, 수령인, 연락처, 우편번호, 도로명 주소, 상세주소, 기본 배송지 여부
- 회원별 최대 개수는 이번 단계에서 제한하지 않는다.
- 첫 저장 배송지는 자동으로 기본 배송지가 된다.
- 기본 배송지 삭제 시 남은 배송지 중 가장 최근 수정된 항목을 기본으로 지정한다.
- 기본 배송지는 목록 첫 번째에 표시한다.
- 배송지를 선택하면 주문서 초안에 복사하며 이후 주소록 수정이 이미 생성된 주문을 바꾸지 않는다.

### 4.2 주소 검색

- 공식 최신 CDN `t1.kakaocdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js`와 `kakao.Postcode`를 사용한다.
- 외부 npm 래퍼는 추가하지 않는다.
- 우편번호 검색은 팝업으로 열고, 결과의 5자리 우편번호와 도로명 주소를 반영한다.
- 검색 완료 후 상세주소 입력으로 포커스를 이동한다.
- 검색 실패 시 원인을 안내하고 `다시 시도`와 `직접 입력`을 제공한다.

### 4.3 주문서 연결

- 화물 택배 배송 또는 개별 화물 운송 상품이 하나라도 있으면 배송지를 사용한다.
- 직접 수령만 있으면 기존 수령인·연락처 입력만 유지하고 배송지 관리 UI를 숨긴다.
- 선택 배송지가 없으면 제출 시 배송지 영역으로 이동해 추가를 안내한다.
- 배송 요청사항은 배송지 주소록이 아니라 주문 초안에만 저장한다.

## 5. UX 원칙

- 주문서에서는 전체 주소 폼을 항상 펼치지 않고 선택된 배송지 요약을 먼저 보여준다.
- 관리 화면은 목록과 편집 폼을 동시에 복잡하게 노출하지 않고 단계적으로 전환한다.
- 삭제는 확인 대화상자를 중첩하지 않고 5초 실행 취소 토스트로 복구한다.
- 작성 중인 배송지 값이 있으면 닫기·취소·Escape 전에 이탈 여부를 확인한다.
- 팝업과 바텀시트의 등장 애니메이션은 180~220ms이며 `prefers-reduced-motion`에서는 제거한다.
- 브랜드 색상은 현재 선택·포커스·주 행동에만 사용한다.
- 주소 검색 결과 필드는 읽기 전용임을 시각·의미상 구분하고, 수동 입력 모드에서만 편집 가능하게 한다.

## 6. 성공 기준

- [x] 저장된 배송지를 선택하면 주문서 수령 정보와 주소가 즉시 갱신된다.
- [x] 추가·수정·삭제·기본 지정이 새로고침 후에도 유지된다.
- [x] 카카오 검색 성공 시 우편번호와 도로명 주소가 채워지고 상세주소로 포커스가 이동한다.
- [x] 외부 스크립트 실패 시 수동 입력으로 주문을 계속할 수 있다.
- [x] 직접 수령 전용 주문에는 배송지 카드가 보이지 않는다.
- [x] 모달·시트에서 Tab 포커스가 빠져나가지 않고 닫힌 뒤 실행 버튼으로 복귀한다.
- [x] 모든 주요 버튼·입력이 최소 44px이며 모바일 가로 스크롤이 없다.
- [x] TypeScript, ESLint, 단위 테스트, E2E와 반응형 회귀 검사를 통과한다.

## 7. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 카카오 스크립트 또는 팝업 차단 | 주소 입력 중단 | 상태별 오류 안내, 재시도, 수동 입력 제공 |
| 브라우저 저장소 손상·만료 | 배송지 목록 유실 | version 검증, 30일 만료, 안전한 초기화 |
| 모의 회원 간 주소 혼합 | 개인정보 노출처럼 보임 | 로그인 회원 ID로 주소를 분리 |
| 모달 포커스·스크롤 누수 | 키보드·모바일 사용성 저하 | focus trap, focus return, body scroll lock, E2E 검증 |
| 주소록과 주문 초안 값 불일치 | 잘못된 배송지 주문 | 선택 시 명시적 복사, 제출은 주문 초안 스냅샷 사용 |
